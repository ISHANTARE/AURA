## Key Decisions Made (with rationale)

1. **One scheduling authority — `ReminderSchedulingService`** (`lib/features/reminders/domain/services/reminder_scheduling_service.dart`). All paths (voice AI, manual sheet, alarm modal, background actions) go through it: persist `reminders_schedule` rows → cancel → schedule → write `notification_logs`. *Rejected:* keeping the split-brain (manual inline scheduling) or reviving the dead `ScheduleReminderUseCase`/`ReminderScheduler` (both deleted).
2. **Notification IDs: deterministic FNV-1a codec** (`notification_ids.dart`), keys `item:<id>` / `rem:<rowId>` / `item:<id>:wd<n>` / `snooze:<id>`, reserved consts 10001–10005. Golden vectors pinned in tests. *Rejected:* persisted `notif_id` DB column (schema v4 + backfill for identical reliability) and a registry table (breaks on clear-data). **Never change the hash without re-triggering the `notif_scheme_migrated_v2` guard.**
3. **Recurrence: native weekly OS repeats** (`matchDateTimeComponents: DateTimeComponents.dayOfWeekAndTime`) for `DAYS:` alarms + `resynchronizeAll()` sweep as repair path. `SPECIFIC_DATE:` stays one-shot.
4. **Gemini as out-of-box default** (user decision): OpenAI-compatible endpoint `https://generativelanguage.googleapis.com/v1beta/openai/` + `gemini-2.0-flash`. Config precedence unified: user prefs > dart-define > dotenv > default. *Rejected:* NVIDIA NIM default, forced-setup-no-default.
5. **Typed LLM errors, no silent config fallback:** auth/model errors throw `LlmApiException` (surface "Open AI Settings"); transient errors fall back to `LocalIntentParser` but set `CaptureState.aiNotice` shown as a banner. *Rejected:* old catch-all → invisible local-parser degradation (the audit's worst UX bug).
6. **Voice locale: device default + Settings override** (`VOICE_LOCALE` pref, `kVoiceLocalePrefKey`); final transcript preferred over partials with a 500 ms grace wait. *Rejected:* hardcoded en-IN (was restricting market).
7. **Workspace routing: hint-vs-real-names** (exact → fuzzy token → generic taxonomy fallback → suggest-new). Taxonomy in `workspace_taxonomy.dart` with a purity test banning dev-specific tokens (vit/vtop/gate/iit/pyq/ishan).
8. **API key in `flutter_secure_storage`** via `SecretStore` (`core/security/secret_store.dart`) with one-time prefs migration guarded by `secure_migration_v1`; `.env` removed from pubspec assets (dotenv kept only as legacy dev harvest).
9. **Onboarding gate in Riverpod** (`OnboardingGateNotifier`, `app_router.dart:49`) — redirect guards ALL routes except `/onboarding`, `/share`, `/capture-overlay`; Reset App Data calls `.reset()`. *Rejected:* keeping the global `_onboardingCompleteChecked` flag (Reset bypass + deep-link bypass).
10. **Play policy: removed `USE_EXACT_ALARM`**, kept `SCHEDULE_EXACT_ALARM`; probe `Permission.scheduleExactAlarm.status` before scheduling, else `inexactAllowWhileIdle` + user-visible notice.
11. **Unified `AuraChannelRegistrar.kt`** registers overlay/DND/speech channels identically for BOTH engines (`isPrimaryEngine` flag controls the static `AuraOverlayService.methodChannel` — only MainActivity sets it, or orb taps break). Ringtone picker keeps deprecated `startActivityForResult` — FlutterActivity is not a ComponentActivity, so Activity Result API is unavailable; isolated to one method with a comment.
12. **Scope decision (user):** code + tests + policy-ready; store listing/signing/privacy-policy explicitly deferred.

## Known Issues & Pitfalls

1. **FK constraint on reschedule:** `notification_logs.reminderId` → `RemindersSchedule.id`. Deleting schedule rows without deleting their logs first trips FOREIGN KEY (tests caught this). Always use `_deleteScheduleRowsForItem()` in the service — never bare-delete `reminders_schedule` for an item.
2. **`tz.local` throws LateInitializationError** if timezone was never initialized. `NotificationService._ensureTz()` guards the schedule methods; test files must `tz.initializeTimeZones()` + set UTC in `setUpAll`.
3. **SharedPreferences caches its first load process-wide** — constructor-time hydration is untestable across tests. `OnboardingGateNotifier` tests avoid it (drive via complete/reset/hydrate); the notifier has `mounted` guards after every await.
4. **`MissingPluginException` is an `Error`, not `Exception`** — `on Exception catch` won't catch it. SecretStore uses bare `catch`; keep that pattern for platform-channel-adjacent code.
5. **`permission_handler`, not the notifications plugin**, exposes exact-alarm state reliably (`canScheduleExactAlarms()` was undefined on plugin 17.2.2).
6. **Two Flutter engines exist** (main + capture overlay). Any new native channel MUST be registered in `AuraChannelRegistrar.kt` or it will silently no-op depending on which engine is foreground. Only the primary engine may set `AuraOverlayService.methodChannel`.
7. **Windows/Git-Bash gotchas:** `adb` not on PATH — use `/c/Android/sdk/platform-tools/adb.exe` (SDK at `C:\Android\sdk`); MSYS mangles `/sdcard/...` paths — set `MSYS_NO_PATHCONV=1`; binary `adb exec-out screencap -p` corrupts — screencap to file then `adb pull`. The Bash tool's safety classifier intermittently gates commands ("temporarily unavailable") — retry; it clears in minutes.
8. **`isOnlineProvider`** is now a StreamProvider (canonical, in `core/providers/connectivity_provider.dart`, seeded by an immediate probe). `CaptureNotifier` no longer watches it — it awaits `ConnectivityService.isOnline()` at the decision point. Don't reintroduce a snapshot bool into the notifier's constructor (it rebuilt mid-capture on connectivity flips).
9. **`watchTodayFocus` is bounded on both ends and takes `now`** — callers must re-subscribe on day change (`dayRefreshProvider`, ticked at midnight + on resume via `app.dart`). A drift watch will NOT roll over by itself.
10. **Snooze moves `Items.fireAt`** — overdue stats depend on this staying in sync. Any new snooze-like flow must update the DB, not just the OS notification.
11. **Legacy tolerance:** notification-tap parser accepts bare UUID payloads (pre-codec schedules) and `alarm:`/`item:`/`route:` grammar — keep during the upgrade window.

## Lessons Learned

- **The audit was directionally right but wrong in details** — e.g., it claimed every user sees "Good morning, Ishant", but that use case was dead code; the live bugs were subtler (settings fallback, briefing screen). Always verify findings against source before fixing.
- **Exploration paid for itself 3×:** the three parallel agents surfaced ~20 defects the audit missed (alarms ring once ever, DND replay a total no-op, broken alarm tap-through, capture-engine channel gaps, share FK crash) — several worse than anything in the audit.
- **Tests caught a real bug in my own fix** (the FK constraint on reschedule) within minutes of writing them — the "add tests per phase" discipline is what made the 72-test suite trustworthy.
- **Kotlin surprises:** `FlutterActivity.getInitialRoute()` returns `String?` (build broke once); `RecognizerIntent.getVoiceDetails()` is not safely usable — dropped the dynamic locale-list feature rather than ship a fragile API (Settings uses a curated static list).
- **The intermittent tool-classifier gating** cost more wall-clock than any code problem; the workaround was always just "keep doing file work, retry the command later".
